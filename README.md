# sr-modkit

Тулинг для моддинга Space Rangers HD: A War Apart — с прицелом на расширение
VSCode (скаффолд мода, сборка, LSP для скриптового языка, визуальный
конструктор).

Спека CLI `srmod` (раскладка мода, конвейер сборки, конфиг) —
[docs/STAGE0.md](docs/STAGE0.md): источник мода — текстовый `.rsm`, собирается
`rsmc.exe`; rson-ветка остаётся запасной.

## CLI `srmod` (этап 0)

```sh
python -m srmod doctor [project]           # конфиг, живые пробы rsmc/RScript/BlockParEditor
python -m srmod new DEST --name NAME       # скаффолд минимального мода
python -m srmod build [project]            # медиа -> язык -> rsmc -> dat -> pkg
python -m srmod lint [project]             # DText в dialogMsg, цифровые имена state
python -m srmod watch [project] [--once]   # пересборка по хэшам исходников
python -m srmod import RSON [project]      # чужой .rson -> раскладка .rsm
python -m srmod verify [project] --gate    # rsmc vs rson для импортированного мода
```

Ни один из внешних инструментов (`rsmc.exe`, `RScript.exe`,
`BlockParEditor.exe`, [rson-decompiler](https://github.com/ArtYudin89/rson-decompiler))
в репозиторий не входит — пути настраиваются в `srmod doctor` (машинный
`%APPDATA%\srmod\config.json` или автодетект сиблингов). Подробности,
включая найденные грабли `rsmc`/`BlockParEditor` — в [docs/STAGE0.md](docs/STAGE0.md).
Windows-only.

## data/lexicon.json

Единый машиночитаемый словарь скриптового языка. Кормит сразу три вещи:
TextMate-грамматику для подсветки, автодополнение и hover в LSP, линтер арности.

Собирается из трёх независимых источников:

| Источник | Что даёт |
|---|---|
| `RScript_4.12f/Schemes/RangersCode.json` | авторитетный список имён и категорий — из самого RScript |
| `Modding_Manual/Script functions list.txt` | описания функций и аргументов, пометка «Опционально» |
| `decompile_result/**/*.rson` | наблюдаемая арность вызовов и живые примеры |

Пересборка:

```sh
python tools/build_lexicon.py --report
```

Пути к источникам по умолчанию — `../rson_decompiler`, переопределяются ключами
`--scheme`, `--manual`, `--corpus`, `--out`.

### Что внутри

```jsonc
"ShipMoney": {
  "kind": "function",              // function | function_custom | constant | keyword
  "summary": "возвращает или устанавливает текущее количество денег корабля",
  "params": [
    {"index": 1, "optional": false, "description": "корабль"},
    {"index": 2, "optional": true,  "description": "какое количество установить…"}
  ],
  "notes": ["Примечание: Функция не позволит установить количество денег ниже 0…"],
  "arity": {"min": 1, "max": 2, "fixed": false, "observed": {"1": 2081, "2": 1055}},
  "examples": ["ShipMoney(Player(),ShipMoney(Player())-cost);"],
  "signature": {"min": 1, "max": 2, "source": "manual", "lintable": true},
  "sources": ["scheme", "manual", "corpus"]
}
```

**`signature` — то, что нужно потребителю**; `params`/`arity` оставлены для
отладки и для показа в подсказках. `max: null` = вариадическая функция.
`lintable: false` значит «диапазон ненадёжен, показывать как подсказку, но не
подчёркивать ошибкой» — так помечены случаи, где мануал и корпус разошлись.

Рядом лежат `manual_only` (описано в мануале, но в языке не существует — теги
датников, читы; годится только как справка) и `corpus_unknown_top` — самые
частые имена вне словаря: это пользовательские функции модов, их LSP обязан
резолвить из проекта.

  срабатываний**

## Известные ограничения

- **Типов аргументов нет.** Ни один источник не хранит их машинно — в мануале
  это проза. Диагностика возможна только по числу аргументов.
- **57 расхождений мануала и корпуса** — это пробелы мануала (незадокументи-
  рованные опциональные аргументы, вариадические `Format`, `ListBox`), а не
  ошибки разбора. Такие функции помечены `lintable: false`.
- Разбор мануала отсекает нумерованные перечисления допустимых значений: они
  неотличимы от списка аргументов, кроме трёх признаков — нумерация с нуля,
  подзаголовок-разделитель перед ними и разрыв в нумерации.

## Лицензия

Условие простое: берёте код `srmod`/`tools/` — открывайте свой. Это касается и
копирования кусков в свой файл, и поставки инструмента в составе сборки.
Отдельная программа, которая просто вызывает `srmod` как внешний процесс и
обменивается с ним файлами, производной работой не считается — но если вы
кладёте эти файлы внутрь своего дистрибутива, вы их распространяете, и GPL
распространяется вместе с ними.

**Граница лицензии.** `rsmc.exe`, `RScript.exe`, `BlockParEditor.exe` и
[rson-decompiler](https://github.com/ArtYudin89/rson-decompiler) — чужие
инструменты, GPL их не покрывает и не может: ни у одного из первых трёх нет
собственной лицензии, поэтому они и не входят в этот репозиторий (только пути
в конфиге). Ресурсы самой игры лицензией тоже не покрыты — их в репозитории
нет и быть не должно.
