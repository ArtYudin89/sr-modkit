# sr-modkit

Инструмент для сборки модов к **Space Rangers HD: A War Apart**.

Мод для «Рейнджеров» — это папка с несколькими файлами, и часть из них игра
понимает только в собранном (двоичном) виде. Собирать их вручную неудобно:
надо в правильном порядке прогнать три чужие программы, не перепутать кодировку
текста и не забыть сгенерировать служебные файлы, без которых мод либо не
появится в списке, либо будет молчать в диалогах.

`srmod` делает это одной командой и **проверяет типовые ошибки до того, как мод
уедет к игрокам**. Программистом быть не нужно: если вы умеете писать скрипты
для «Рейнджеров» в RScript, этого достаточно.

> Работает только под Windows — потому что под Windows работают программы, к
> которым `srmod` обращается.

## Что нужно установить

Четыре вещи. Ни одна из них не входит в `sr-modkit` — их пишут другие люди, и
класть чужие программы в свой архив я не имею права. Скачайте их сами, один раз.

| Что | Зачем | Где взять |
|---|---|---|
| **Python** 3.9 или новее | на нём написан сам `srmod` | [python.org](https://www.python.org/downloads/) — при установке **обязательно** поставьте галочку «Add Python to PATH» |
| **rsmc.exe** | превращает текст скрипта в игровой `.scr` | релизы RScript у автора: [github.com/indiemagpie](https://github.com/indiemagpie) (файл `rsmc.zip`) |
| **RScript.exe** 4.14f+ | нужен, только если открываете чужие моды (`srmod open` / `srmod import`) | там же |
| **BlockParEditor.exe** | собирает текстовые файлы игры в `.dat` | [github.com/indiemagpie](https://github.com/indiemagpie) |
| **rson-decompiler** | картинки (`.png` → `.gi`) и работа с `.dat` | [github.com/ArtYudin89/rson-decompiler](https://github.com/ArtYudin89/rson-decompiler) — кнопка «Code» → «Download ZIP» |

Разложите их куда угодно — путь вы укажете один раз (см. следующий раздел).

Затем скачайте сам `sr-modkit` (кнопка «Code» → «Download ZIP», распакуйте
например в `C:\tools\sr-modkit`) и один раз выполните:

```
pip install -e C:\tools\sr-modkit
```

После этого команда `srmod` работает из любой папки. Дальше в примерах — она.

> Не хотите ничего устанавливать? Можно и без этого: откройте командную строку
> **внутри папки `sr-modkit`** и вместо `srmod` пишите `python -m srmod`.
> Работает так же, но только из этой папки.

```
python --version
```

Если пишет `Python 3.9.x` (или больше) — всё хорошо. Если «не является внутренней
или внешней командой» — Python не добавлен в PATH, переустановите его с галочкой
«Add Python to PATH».
</details>

## Шаг 1. Показать `srmod`, где лежат программы

```
srmod doctor
```

Эта команда ничего не меняет — она смотрит, что нашлось, и запускает каждую
программу, чтобы убедиться, что она отвечает. Вывод выглядит так:

```
== Инструменты ==
  rsmc       [autodetect]: C:\tools\rsmc\rsmc.exe
  rscript    [autodetect]: C:\tools\RScript_4.14f\RScript.exe
  blockpar   [autodetect]: C:\tools\BlockParEditor_1.9\BlockParEditor.exe
  ...
== Пробы ==
  rsmc:     ... — отвечает: "rsmc - .rsm -> .scr compiler"
```

Если напротив чего-то написано **НЕ НАЙДЕН** — создайте файл
`C:\Users\<вы>\AppData\Roaming\srmod\config.json` (папку `srmod` сделайте сами)
и впишите пути:

```json
{
  "tools": {
    "rsmc":       "C:/tools/rsmc/rsmc.exe",
    "rscript":    "C:/tools/RScript_4.14f/RScript.exe",
    "blockpar":   "C:/tools/BlockParEditor_1.9/BlockParEditor.exe",
    "game":       "C:/Games/Space Rangers HD A War Apart",
    "decompiler": "C:/tools/rson-decompiler"
  }
}
```

Черта в путях — прямая (`/`). Обратную в этом формате пришлось бы удваивать
(`"C:\\tools\\rsmc\\rsmc.exe"`), прямая работает и так. Снова запустите
`doctor`, пока все строки не перестанут ругаться.

## Шаг 2. Сделать мод

```
srmod new C:\mods\MyFirstMod --name MyFirstMod
```

Получится готовая заготовка — **рабочий** мод с комментариями в каждом файле:
звезда, планета, корабль игрока, NPC с диалогом в две реплики, тексты в
`Lang.txt` и два примера графики (иконка из `.png` и маленькая анимация).
Его можно сразу собрать и запустить, а потом править по комментариям.
Нужен голый каркас без примеров — добавьте флаг `--minimal`.

Имя (`--name`) — латиницей, без пробелов, начинается с буквы. Оно попадёт
сразу в три места и везде должно совпадать, поэтому менять его потом
неудобно — выберите сразу.

## Шаг 3. Собрать

```
srmod build C:\mods\MyFirstMod
```

Если всё хорошо — последняя строка будет `OK: сборка завершена`. Если нет,
`srmod` остановится и скажет, что именно не так (см. «Если что-то пошло не
так»).

## Шаг 4. Поставить в игру

```
srmod deploy C:\mods\MyFirstMod
```

Команда создаёт в `Mods` игры ссылку (junction) на папку `build/` вашего
мода — по тому пути, который записан в `srmod.json` в поле `install`.
Делается один раз: дальше каждая пересборка сразу «видна» игре, копировать
ничего не нужно.

Путь `install` важен: при сборке он зашивается внутрь служебного файла
`CacheData.dat`. Хотите другое расположение (например,
`Mods/MyMods/MyFirstMod`) — впишите его в `install`, пересоберите и повторите
`deploy`.

Запустите игру, включите мод в менеджере модов, начните **новую** игру.

Если раскладывать мод игрокам — отдаёте содержимое `build/`: это и есть
готовый мод, без исходников.

## Что внутри мода

```
MyFirstMod/
  srmod.json            настройки: имя, куда ставится, языки
  src/                  ← все исходники, здесь вы и работаете
    ModuleInfo.txt      что игрок увидит в списке модов: название, автор, описание
    CFG/
      Main.txt          связка скрипта с игрой
      Rus/Lang.txt      тексты мода (комментарии можно — сборка их вырежет)
    DATA/
      Script/
        MyFirstMod.src/ сам скрипт, разложенный по модулям:
          main.rsm      имя мода + список модулей
          vars.rsm      переменные
          world.rsm     звёзды, планеты, корабли, группы
          states.rsm    поведение групп
          dialogs.rsm   диалоги
          code.rsm      функции, которые вызывает игра
      Items/            примеры графики: .png → .gi, папка кадров → .gai
  build/                появляется после сборки: готовый мод для игры
```

`build/` — результат, а не исходники: руками там ничего не правится, каждая
сборка делает его заново. В нём нет ни исходников, ни комментариев — ровно
то, что нужно игре.

**Заполните `src/ModuleInfo.txt`** — `Author`, `SmallDescription`, `FullDescription`.
Это то, что игрок прочитает в списке модов; пустые поля выглядят заброшенно.

### Правило про кодировку — самое важное

Файлы `ModuleInfo.txt`, `Main.txt`, `Lang.txt` игра читает **только в кодировке
UTF-16 LE**. Сохраните их «просто в блокноте» (в UTF-8) — и текст в игре
превратится в кракозябры, причём **без единой ошибки при сборке**: программа,
которая их собирает, молча портит такой файл.

Поэтому `srmod` проверяет кодировку сам и отказывается собирать. Как сохранять
правильно:

- **Блокнот Windows**: Файл → Сохранить как → внизу «Кодировка» → **Юникод**
- **Notepad++**: Кодировки → **UCS-2 LE BOM**

Файл скрипта `.rsm` — наоборот, обычный **UTF-8**, его портить нечем.

## Команды

| Команда | Что делает |
|---|---|
| `srmod doctor` | проверяет, всё ли на месте и работает |
| `srmod new ПАПКА --name ИМЯ` | создаёт заготовку мода (`--minimal` — без примеров) |
| `srmod build ПАПКА` | собирает мод: `src/` → `build/` (`--deploy` — и сразу в игру) |
| `srmod deploy ПАПКА` | ставит мод в игру ссылкой на `build/` (один раз) |
| `srmod lint ПАПКА` | ищет в скрипте ошибки, которые сборка пропустит, а игра — нет (`--no-dsl` — без сверки со схемой языка) |
| `srmod watch ПАПКА` | следит за `src/` и пересобирает сам после каждого сохранения |
| `srmod open ПАПКА-МОДА ПАПКА` | разбирает ЛЮБОЙ установленный мод в исходники: скрипт → `.rsm`, датники → `.txt`, картинки → `.png`, архивы → папки |
| `srmod import ЧУЖОЙ.rson ПАПКА` | то же для одиночного `.rson`-файла скрипта |
| `srmod verify ПАПКА --rebuild ПАПКА-МОДА` | пересобирает разобранный мод и сверяет с оригиналом файл в файл |
| `srmod verify ПАПКА --gate` | сверяет сборку чужого мода со старым способом сборки |

`open` ничего не портит: всё, что не разбирается обратно **байт в байт**
(редкие форматы картинок, огромные архивы, старые скрипты), остаётся в
исходниках бинарником как есть — мод после пересборки идентичен оригиналу.
Проверить это самому — `--verify` при открытии.

`watch` удобен, когда правите скрипт: оставьте окно открытым, и после каждого
сохранения мод пересоберётся сам. Остановить — `Ctrl+C`.

## Не хочется набирать команды: расширение для VS Code

В папке `extension/` лежит расширение к [VS Code](https://code.visualstudio.com/)
— те же команды, но кнопками, плюс помощь при написании скрипта:

- подсветка `.rsm` и датниковых `.txt` (`Lang.txt`, `Main.txt` и всё в `CFG/`),
  заготовки (напишите `dialogMsg` и нажмите Tab);
- **подсказки по функциям игры**: 977 имён с описанием и числом аргументов —
  начните набирать `Change` и увидите `ChangeState` с пояснением;
- **переход к определению** (F12): с `ChangeState("StX")` или `state: "StX"` —
  на саму декларацию, с `import from './states.rsm'` — в файл;
- **подсказки полей**: поставили `{` внутри `planet(...)` — видите список полей
  именно планеты; начали значение `government: "` — видите допустимые значения.
  Списки не выдуманы, они вынуты из самого компилятора `rsmc`, и там, где он
  значение **не проверяет**, подсказка честно об этом пишет;
- замечания `srmod lint` при сохранении — сразу в панели «Проблемы», с
  переходом на нужную строку;
- «Создать новый мод…», «Собрать», «Поставить в игру», «Открыть готовый мод…»
  — из палитры команд (`Ctrl+Shift+P`, наберите `srmod`).

Поставить: скачайте `sr-modkit-*.vsix` из релизов (или соберите сами, см.
`docs/EXTENSION.md`) и в VS Code — `Ctrl+Shift+P` → **Extensions: Install from
VSIX…**. Расширению нужен установленный `srmod`; если вы не делали
`pip install -e`, укажите папку `sr-modkit` в настройке `srmod.repoPath`.

Подробности — `extension/README.md`.

## Если что-то пошло не так

`srmod` намеренно останавливается на ошибках, которые иначе всплыли бы уже у
игроков. Что означают сообщения:

**`UTF-8 без BOM с кириллицей — запрещено для датников`**
Текстовый файл сохранён не в той кодировке. См. раздел про кодировку выше.

**`scriptName("Имя") != srmod.json:name ("Другое")`**
Имя мода записано в трёх местах, и они разошлись: в первой строке `.rsm`, в
`srmod.json` и в имени файла скрипта. Приведите к одному.

**`rsmc warning ... has no existing Script^{...} block`**
Внутренняя ошибка сборки текстов. Обычно означает, что имя мода поменяли не
везде — см. пункт выше.

**Мод не появился в списке модов игры**
Проверьте `ModuleInfo.txt` (должен быть в корне папки мода) и что папка лежит
именно там, куда указывает `install`.

**Мод есть, но персонажи молчат / вместо текста пусто**
Тексты не попали в игру. Пересоберите и убедитесь, что `Lang.txt` в UTF-16 LE.

**`srmod lint` ругается на `DText(...) внутри code:`**
Текст диалога должен лежать в `text:`, а не вызовом `DText(...)` внутри
`code:`. Такой вызов `rsmc` молча пересобирает по-своему (двойная подстановка
плюс лишняя пустая реплика), и после следующей сборки текст в игре может
превратиться в служебный ключ вида `Script.Имя.12`. Чаще всего вылезает на
чужих модах, открытых через `import`, — такие моды собирайте через
`srmod verify --gate` / rson-ветку.

**`srmod lint` ругается на состояние с числовым именем**
Состояние, названное числом (`"1"`, `"20"`), ломает переходы: `ChangeState(1)`
уйдёт не туда. Переименуйте по-человечески.

**`srmod lint`: «задано строкой, а поле флаговое»**
Раса, владелец, тип корабля и подобные поля компилятор понимает только списком:
`race: ["People"]`. Если написать `race: "People"`, сборка пройдёт молча, но
значение до игры не доедет — проверено побайтово. Возьмите значение в скобки.

**`srmod lint`: «поле … не известно»**
Опечатка в имени поля. У большинства деклараций `rsmc` такое поле молча
выбрасывает, так что сборка пройдёт, а поле просто не подействует. Правильные
имена подскажет само сообщение (и автодополнение в VS Code).

Не нашли свою ошибку — [заведите Issue](../../issues) и приложите текст
сообщения целиком.

## Для тех, кому интересно устройство

Подробное описание формата, конвейера сборки и всех найденных подводных камней
(включая ошибки в чужих программах, которые пришлось обходить) —
в [docs/STAGE0.md](docs/STAGE0.md). Устройство расширения VS Code — в
[docs/EXTENSION.md](docs/EXTENSION.md).

<details>
<summary><b>data/lexicon.json</b> — словарь скриптового языка (для авторов
редакторов и подсветки синтаксиса)</summary>

Машиночитаемый словарь языка скриптов: имена функций, их описания и число
аргументов. Годится для подсветки синтаксиса, автодополнения и проверки вызовов.

Собран из трёх независимых источников:

| Источник | Что даёт |
|---|---|
| `RScript_4.12f/Schemes/RangersCode.json` | список имён и категорий — из самого RScript |
| `Modding_Manual/Script functions list.txt` | описания функций и аргументов |
| корпус декомпилированных скриптов | наблюдаемое число аргументов и живые примеры |

Пересборка: `python tools/build_lexicon.py --report` (пути по умолчанию —
`../rson_decompiler`, меняются ключами `--scheme`, `--manual`, `--corpus`, `--out`).

Формат записи:

```jsonc
"ShipMoney": {
  "kind": "function",
  "summary": "возвращает или устанавливает текущее количество денег корабля",
  "signature": {"min": 1, "max": 2, "source": "manual", "lintable": true},
  "arity": {"min": 1, "max": 2, "observed": {"1": 2081, "2": 1055}},
  "examples": ["ShipMoney(Player(),ShipMoney(Player())-cost);"]
}
```

`signature` — то, что нужно потребителю; `max: null` — переменное число
аргументов; `lintable: false` — «показывать подсказкой, но не подчёркивать
ошибкой» (мануал и корпус разошлись).

Текущая сборка: 977 записей (678 встроенных функций, 41 из UtilityFunctionsPack,
242 константы, 16 ключевых слов), 702 сигнатуры, из них 609 пригодны для строгой
проверки. Прогон по корпусу из 330 файлов: 183 657 вызовов, 0 ложных срабатываний.

**Чего в словаре нет:** типов аргументов. Ни один источник не хранит их
машинно — в руководстве это обычный текст. Поэтому проверять можно только
количество аргументов, не их смысл.
</details>

<details>
<summary><b>data/rsm-dsl.json</b> — описание деклараций языка <code>.rsm</code>
(поля, обязательные аргументы, допустимые значения)</summary>

Дополняет `lexicon.json`: тот про функции внутри кода, этот — про 17 деклараций
самого языка `.rsm` (`star`, `planet`, `ship`, `group`, `state`, `dialog`,
`dialogMsg`, `dialogAnswer`, `place`, `item`, `ether`, `groupLink`, `starLink`,
`constellation`, `scriptName`, `globalVar`, `localVar`).

Оба источника — **сам компилятор `rsmc`**, поэтому список ровно тот, который он
и понимает:

| Источник | Что даёт |
|---|---|
| таблица строк `rsmc.exe` | имена полей, позиционные аргументы, обязательные поля, форма элементов массивов `transitions` и `answers` |
| опрос живого `rsmc build` | допустимые значения: в рабочий скрипт подставляется негодное значение, из ответа `(expected one of: …)` читается список |

Пересборка: `python tools/build_dsl_schema.py` (ключи `--rsmc`, `--out`).

```jsonc
"planet": {
  "positional": ["name"],
  "fields": ["star", "race", "owner", "economy", "government",
             "rangeMin", "rangeMax", "dialog"],
  "required": ["star"],
  "enums": {
    "government": {
      "values": ["GroupToggle", "Anarchy", "Dictatorship",
                 "Monarchy", "Republic", "Democracy"],
      "validated": true
    }
  }
}
```

**`validated: false` — важная пометка.** Шесть полей `rsmc` не проверяет
вообще: `item.type`, `item.useless`, `dialogAnswer.answerCommand`,
`ether.type`, `groupLink.rel1`, `starLink.hole`. Он принимает там любую строку —
в том числе вместо числа и флага. Опечатка в таком поле собирается без единого
предупреждения и вылезает уже в игре, поэтому подсказки в редакторе пишут об
этом прямым текстом, а подчёркивать ошибкой такие значения нельзя: полного
списка допустимых значений не знает никто, кроме самой игры.
</details>

Коротко: берёте код `srmod` — открывайте свой. Это касается и копирования кусков
в свой файл, и поставки инструмента в составе сборки. Программа, которая просто
вызывает `srmod` как отдельный процесс, производной работой не считается.

**Что лицензией не покрыто:** `rsmc.exe`, `RScript.exe` и `BlockParEditor.exe` —
чужие программы, они не входят в этот репозиторий (только пути к ним в
настройках). Ресурсы самой игры принадлежат правообладателям; их здесь нет и
быть не должно. **Моды, собранные с помощью `srmod`, принадлежат вам** —
инструмент не накладывает на них никаких условий.
