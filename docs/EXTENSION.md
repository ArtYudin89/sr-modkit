# Этап D — расширение VS Code (`extension/`)

Спека и решения по расширению. Пользовательская часть — `extension/README.md`,
здесь только то, что нужно знать при правке кода.

## Принцип: расширение не умеет собирать моды

Вся логика сборки живёт в Python-пакете `srmod`. Расширение — тонкая обёртка:
запускает те же подкоманды, что модер набрал бы руками, и показывает вывод.
Ни одной проверки, продублированной на JS, быть не должно — иначе CLI и
расширение разъедутся, и придётся чинить в двух местах. Единственное, что
расширение разбирает само, — формат строк `srmod lint` (`путь:строка: текст`),
и тот же формат описан problem matcher'ом `$srmod-lint` для задач.

`syntaxes/rangers-script.tmLanguage.json` и `data/rsm-dsl.json` — канон лежит в
корне репозитория, внутри `extension/` живёт копия: `vsce` пакует только файлы

`python tools/sync_extension.py [--regen]`; в git они тоже лежат, чтобы свежий
клон запускался по F5 без предварительной генерации.

## Откуда берутся подсказки: `tools/build_dsl_schema.py`

`data/rsm-dsl.json` описывает все 17 деклараций языка. Оба источника — сам
компилятор, ничего не выдумано и не списано с чужих плагинов:

1. **Списки полей** — из таблицы строк `rsmc.exe` (UTF-16LE). Парсер держит
   имена полей подряд между собственными сообщениями об ошибках: блок
   декларации начинается с `state(...) needs a name string` и кончается на
   `unknown state(...) field "` либо на сообщении следующей декларации.
   Оттуда же — позиционные аргументы (`groupLink(...) needs (fromGroup,
   toGroup, {...}?)`), обязательные поля (`... requires a "star" field`) и
   форма элементов массивов (`transitions entry requires a "to" field`).
2. **Значения перечислений** — опросом живого `rsmc build`: в заведомо рабочий
   минимальный скрипт подставляется негодное значение, и из ответа
   `(expected one of: ...)` читается список.

**Грабли, уже учтённые в коде** (не наступать заново):

- Порог длины строк в exe — **2 символа**, а не 3: иначе теряется поле `at`
  у `item(...)`.
- Последняя декларация (`dialogAnswer`) без ограничителя `unknown ... field`
  сметает в поля весь хвост таблицы строк — 353 «поля» вместо четырёх.
- Выравнивающий мусор секции данных (`jj`, `jjjj`) выглядит как идентификатор
  и попадает в блоки `ship`/`starLink` — отсекается по виду.
- `group(...) needs (name, {planet, state, ...})`: перечисление позиционных
  аргументов обрывается на первом `{`, иначе `state` уезжает в позиционные.
- `globalVar`/`localVar` разбираются одним куском кода, имена полей лежат в
  таблице один раз — блок `globalVar` пустой, форму копируем от `localVar`.

**Что rsmc не проверяет вообще** (снято опросом 2026-08-04): `item.type`,
`item.useless`, `dialogAnswer.answerCommand`, `ether.type`, `groupLink.rel1`,
`starLink.hole` — он принимает любую строку и молча собирает мод. Последние два
ждут число и флаг, но строку тоже съедают: типы значений он не смотрит.
Такие поля помечены `"validated": false`, и подсказка про это пишет прямым
текстом: диагностику «недопустимое значение» по ним давать нельзя, ошибка
вылезет только в игре. Значения `answerCommand`, встречающиеся в шиппенных
модах (`restart/exit/shop/hangar/planet/fastexit`), взяты прогоном по корпусу
и лежат в `OBSERVED` генератора.

## Чем запускается `srmod` (`src/runner.js`)

Три варианта по порядку, результат кэшируется до смены настроек:
`srmod.command` из настроек → `srmod` из PATH (после `pip install -e`) →
`<python> -m srmod` с рабочим каталогом репозитория (`srmod.repoPath` либо
папка над `extension/`, если расширение запущено из исходников).

**`PYTHONIOENCODING=utf-8` обязателен**: `srmod` печатает по-русски, а Python
на Windows при перенаправлении вывода в канал берёт кодировку локали (cp1251) —
в панели вывода была бы каша. `PYTHONUTF8` ставить **нельзя**: он меняет
кодировку по умолчанию для файловых операций, а `srmod` работает с cp1251- и
UTF-16-файлами игры.

`srmod watch` гасится через `taskkill /T /F`: он запускает `rsmc` и
`BlockParEditor`, и без убийства дерева внуки переживут родителя.

## Подсказки (`src/dsl.js`)

Контекст определяется двумя чистыми функциями: `mask()` гасит содержимое строк
и комментариев, сохраняя длину, а `enclosingDecl()` идёт от курсора назад до
незакрытой `(` (незакрытые `{`/`[` по дороге — это объект опций и массивы того
же вызова). «Курсор внутри строки» считается парностью кавычек, а не поиском
кавычки слева: в `planet("P", {` кавычки закрыты, и подсказывать там надо поля.

Тест: `node extension/test/dsl.test.js` — подменяет модуль `vscode` заглушкой и
гоняет провайдеры на настоящем `data/rsm-dsl.json`.

## Тесты

**Без VS Code** (быстро, гоняется всегда):

```
node extension/test/dsl.test.js
```

**В настоящем Extension Host** — активация, регистрация команд, ответы
провайдеров. Профиль пользователя не трогается, всё в отдельных каталогах:

```
Code.exe --user-data-dir <tmp>\u --extensions-dir <tmp>\e ^
         --extensionDevelopmentPath=<repo>\extension ^
         --extensionTestsPath=<repo>\extension\test\integration\index.js
```

Две грабли запуска, обе съедают результат молча:

- **`code.cmd` не пробрасывает код возврата**: заведомо падающий тест тоже даёт
  `0`. Запускать надо `Code.exe` и ждать процесс (`Start-Process -Wait
  -PassThru`), иначе проверка ничего не проверяет.
- **Из терминала внутри VS Code наследуется `ELECTRON_RUN_AS_NODE=1`**, и
  `Code.exe` стартует как node: `bad option: --user-data-dir`. Переменную надо
  снять (заодно `VSCODE_IPC_HOOK`, `VSCODE_NLS_CONFIG`, `VSCODE_PID` и прочие
  `VSCODE_*`, чтобы не приклеиться к работающему экземпляру).

Ещё второй экземпляр не стартует, пока VS Code держит мьютекс обновления
(`Code is currently being updated`) — тогда тест ждёт перезапуска редактора.

## Встроенные функции (`src/lexicon.js`)

977 имён (678 функций движка, 41 из UtilityFunctionsPack, 242 константы,
16 ключевых слов) — автодополнение и hover. Данные — `extension/data/lexicon.json`,
компактная выжимка корневого `data/lexicon.json` (имя, вид, арность, короткое
описание; полные примечания мануала весят 940 КБ и в подсказку не помещаются),
её делает `tools/sync_extension.py`. Провайдер молчит внутри строк и сразу
после `ключ:` — там подсказывает `dsl.js`, и смешивать списки нельзя.

## Переход к определению (`src/definition.js`)

Два случая: `import from './states.rsm'` (путь относительно файла с import) и
любой строковый литерал, совпавший с именем декларации, — `state: "StX"`,
`ChangeState("StX")`, `next: "dMsg2"`. Связи в этом языке именные, поэтому
одного правила хватает на все поля, и таблица «какое поле на что ссылается» не
нужна. Индекс строится по соседним `.rsm` (каталог модуля `<Name>.src/`).

## Диагностика по схеме языка

Живёт в `srmod lint` (Python, `srmod/dsl.py`), не в JS — тогда она работает и в
CLI, и в CI, а расширение просто разбирает её строки. Формат строки —
`путь:строка: важность: текст`, важность английская (`error`/`warning`), иначе
её не понимает problemMatcher VS Code; текст остаётся русским. `error` —
сборка упадёт ИЛИ поле молча не подействует, `warning` — соберётся, но может
сломаться в игре. Отключается флагом `srmod lint --no-dsl`.

## Подсветка датниковых `.txt`

Второй язык `rangers-dat` (`syntaxes/rangers-dat.tmLanguage.json`, тот же
генератор `tools/build_grammar.py`): блоки `Имя ^{` / `~{`, записи
`ключ=значение`, комментарии, а значения-код красятся теми же списками из
схемы RScript. Вешается не на все `.txt`, а на `Lang.txt`/`Main.txt`/
`CacheData.txt`/`ModuleInfo.txt` и всё, что лежит в `CFG/**`. Смоук — 42 файла
реальных модов, 45 953 строки, непокрытых 0; из него же вылезли **безымянные
блоки** (`    ~{`) в Lang.dat, под них правило и расширено.
