# Этап 0 — CLI `srmod` на источнике `.rsm`

Пересборка плана после разбора RScript 4.14f и `rsmc` (2026-07-31). Отменяет
раскладку и конвейер из прежнего плана «источник = JSON-`rson`»; всё, что здесь
не оговорено, остаётся как было.

**Суть перемены.** Источник мода — текстовый `.rsm` (UTF-8, кириллица как есть,
git-diff, модули), собирается автономным `rsmc.exe`. Из конвейера уходят два
шага, которые раньше делали мы: слияние сгенерированной секции `Script` в
`Lang` и ре-ключевание CT-текстов — это делает сам `rsmc`. `RScript.exe` в
основной ветке сборки больше не участвует (нужен только для импорта чужих
модов и для запасной rson-ветки), а вместе с ним уходит и `_dlgwatch`: `rsmc` —
обычная консольная программа без модальных окон.

---

## (а) Раскладка папки мода

Правила прежние: **источник и артефакт различаются расширением и лежат рядом**;
папка мода = то, что кладётся в `Mods\` без копирования; `[S]` — в git,
`[A]` — в `.gitignore`.

```
MyMod/
  srmod.json [S]                  имя, install-путь, языки, точка входа, опции
  ModuleInfo.txt [S]              UTF-16LE BOM
  CFG/
    Main.txt [S]                  → Main.dat [A]
    Rus/ Lang.txt [S] + *.txt [S] → Lang.dat [A]     (секции Script в исходнике НЕТ)
    Eng/ Lang.txt [S] + *.txt [S] → Lang.dat [A]
    CacheData.txt [A]             → CacheData.dat [A]
  DATA/
    Script/
      MyMod.src/ [S]              модули .rsm — единственный источник скрипта
        main.rsm                  scriptName(...) + import from './*.rsm'
        vars.rsm world.rsm places.rsm states.rsm dialogs.rsm
        code_global.rsm code_init.rsm code_turn.rsm code_dialogbegin.rsm
      MyMod.scr [A]               ← rsmc build
      MyMod.txt [A]               ← rsmc пишет ВСЕГДА рядом с -o (таблица CT-ключей)
    Items/ hull.png [S] → hull.gi [A];  hull.gai.src/ [S] → hull.gai [A]
    Panels.pkg.src/ [S] → Panels.pkg [A]
  INSTALL.TXT [A]                 (только если есть .pkg)
  .srmod/state.json [A]           хэши исходников для инкрементальной сборки
```

**Почему модули в `MyMod.src/`, а не россыпью в `DATA/Script/`.** Имена, которые
даёт `RScript --cli -x --split`, безличные (`main/vars/world/places/states/
dialogs/code_*.rsm`) — два скрипта в одном моде затёрли бы друг друга. Суффикс
`.src` у папки-исходника — та же конвенция, что у `*.gai.src/` и `*.pkg.src/`,
и `.gitignore` остаётся плоским:

```
*.scr
*.dat
*.gi
*.gai
*.hai
*.pkg
DATA/Script/*.txt
CFG/CacheData.txt
INSTALL.TXT
.srmod/
```

**Односкриптовый вариант разрешён:** если `MyMod.src/` нет, точкой входа
считается `DATA/Script/MyMod.rsm` (одним файлом, без `import`). Порядок поиска
входа: `srmod.json:script.entry` → `DATA/Script/<name>.src/main.rsm` →
`DATA/Script/<name>.rsm`. Проверено: имя точки входа `rsmc` безразлично
(`MyMod.rsm` вместо `main.rsm` собирается так же), `import from './…'`
разрешается относительно каталога точки входа, одиночный файл без `import`
собирается.

**Что НЕ кладётся в git:** `.scr`, `.txt`-таблица CT рядом с ним, все `.dat`,
`CacheData.*`, `INSTALL.TXT`, собранные медиа и пакеты. `.rson` в `.rsm`-моде
не хранится вовсе — он появляется только во временном каталоге при
`srmod verify --gate` и при импорте.

**Кодировки (гейт сборки, не рекомендация):** `ModuleInfo.txt` и все исходные
`*.txt` для датников — **UTF-16LE + BOM** (в git читаемо через
`.gitattributes` `working-tree-encoding=UTF-16LE-BOM`); `.rsm` — **UTF-8**.
BlockParEditor молча портит UTF-8 на входе («РџСЂРёРІРµС‚», ноль ошибок),
поэтому `srmod build` обязан проверять кодировку входных `.txt` и падать.

## (б) Конвейер `srmod build`

Порядок обязателен: язык готовится ДО вызова `rsmc`, потому что `rsmc` мержит
тексты в уже существующий файл.

| # | Шаг | Чем |
|---|---|---|
| 1 | Медиа: `png→gi`, `*.gai.src/→gai`, `*.hai.src/→hai` | `srgi.py` из rson-decompiler |
| 2 | Стейджинг языка: `CFG/<lang>/Lang.txt` + прочие `*.txt` фрагменты → **временный** файл; в файл основного языка добавляется каркас `Script ^{ <scriptName> ^{ } }`, если его там нет | свой код |
| 3 | Скрипт: `rsmc build DATA/Script/<Name>.src/main.rsm -o DATA/Script/<Name>.scr --lang-txt <врем. Lang.txt>` | `rsmc.exe` |
| 4 | `<врем. Lang.txt>` → `CFG/<lang>/Lang.dat`; неосновные языки — из своих исходников как есть | BlockParEditor |
| 5 | `CFG/Main.txt` → `CFG/Main.dat` | BlockParEditor |
| 6 | Генерация `CFG/CacheData.txt` из `install`-пути → `CacheData.dat` | свой код + BlockParEditor |
| 7 | `*.pkg.src/` → staging (без `png`/`times.json`) → `.pkg` + генерация `INSTALL.TXT` | `srpkg.py` |

Исходный `Lang.txt` на диске не трогаем никогда: `rsmc` пишет в свою копию,
из неё же родится `.dat`. Инкрементальность и `srmod watch` — по хэшам
исходников в `.srmod/state.json`.

### Поведение `rsmc`, проверенное руками (иначе мод уедет к игрокам немым)

1. **`rsmc` всегда пишет `<стем -o>.txt`** рядом с `.scr` — ту же таблицу
   `ключ=текст`, что RScript писал третьим аргументом (UTF-16LE + BOM).
   ⇒ `--lang-txt` **не должен указывать на файл с тем же стемом, что `-o`**:
   таблица затрёт язык до слияния, и вместо мода получится «warning: … has no
   existing Script^{…} block». Именно поэтому временный `Lang.txt` живёт в
   `.srmod/tmp/`, а не рядом с `.scr`.
2. **`--lang-txt` мержит только в уже существующий блок**
   `Script ^{ <scriptName> ^{ … } }`. Пустого каркаса достаточно. Если блока
   нет — `warning` и **`rc = 0`**: сборка «успешна», мод молчит.
   ⇒ шаг 2 конвейера обязателен, а `srmod` обязан **считать `warning:` в выводе
   `rsmc` ошибкой сборки**.
2a. **Код возврата `rsmc` бесполезен: он `0` и на настоящей ошибке.** Проверено:
   несуществующий каталог у `-o` даёт `error: TFileEC.CreateNew. FileName=…`
   и `rc = 0`, файл не создан. ⇒ единственный надёжный контроль — разбор
   stdout на `error:`/`warning:` **плюс** проверка, что `.scr` создан и свежее
   запуска. Каталоги под артефакты `srmod` создаёт сам.
3. **Кодировку целевого файла `rsmc` сохраняет:** cp1251 → cp1251,
   UTF-16LE+BOM → UTF-16LE+BOM, кириллица не портится. Правило «исходники
   датников только в UTF-16LE BOM» остаётся в силе и после переезда.
4. **`--lang-dat` умеет мержить прямо в `.dat`** — проверено на реальном
   `AdvancedArts/CFG/Rus/Lang.dat`: блок `Script^{AdvancedArts}` перезаписан,
   соседняя секция `Artefacts` цела, объём тот же, BlockParEditor 1.9 читает
   результат. Оставляем как опцию (`lang.merge_into: dat`) для модов без
   текстового исходника языка; **основной путь — `--lang-txt`**, чтобы `.dat`
   всегда рождался из BPE и оставался ровно одной зависимости шире.
5. **`scriptName("…")` в `main.rsm` — ключ ко всему:** это и имя блока в
   `Lang`, и префикс CT-ключей (`Script.<Name>.N`), и то, с чем `rsmc` ищет
   блок для слияния. `srmod build` сверяет `scriptName` с `srmod.json:name` и
   с именем выходного `.scr` и падает при расхождении.
6. **`DText(...)` в теле `code:` у `dialogMsg` сохраняется** — ранняя гипотеза
   о его потере ОПРОВЕРГНУТА сверкой инструментами автора (`rsmc build` +
   `RScript --cli -d` обеих сборок): содержимое совпадает, отличается только
   разбиение на строки — `rsmc` выносит сгенерированный из `text:`
   `DText(CT(...))` отдельной строкой, RScript клеит его со следующим
   оператором. Ловушка была в нашем `decompiler.py`: он раскладывает этот
   `DText` то в код узла, то в поле сообщения в зависимости от переноса строки.
   Практический вывод для `srmod`: сверять сборки **только** после склейки
   переносов, иначе получишь ложные расхождения.
7. **`ChangeState(<число>)` разрешается по ИМЕНИ, а не по индексу, если в моде
   есть состояние с таким именем.** Найдено корпусным прогоном на
   `Mod_RevDiplomat`: у мода есть состояния с именами `01`, `1`, `20`;
   исходный `ChangeState(1)` (индекс 1) после `rsmc` превратился в
   `ChangeState(7)` — это индекс состояния, которое НАЗЫВАЕТСЯ `1`.
   ⇒ `srmod lint`: запрещать имена деклараций, состоящие из одних цифр;
   `srmod new` такие имена не генерирует.

### Многоязычность

Сгенерированная секция `Script` уходит только в основной язык
(`primary_lang`). Для остальных автор ведёт свой фрагмент руками с той же
нумерацией ключей — ограничение формата, обойти нечем. `srmod build` после
сборки сверяет наборы ключей всех языков и печатает недостающие.

## (в) `srmod.json` и трёхуровневый конфиг

Хардкода путей нет нигде. Три уровня, каждый следующий перебивает предыдущий:

**1. Машинный — `%APPDATA%\srmod\config.json`** (пути к чужим бинарникам):

```jsonc
{
  "tools": {
    "rsmc":     "C:/claude_sandbox/rson_decompiler/rsmc/rsmc.exe",
    "rscript":  "C:/claude_sandbox/rson_decompiler/RScript_4.14f/RScript.exe",
    "blockpar": "C:/claude_sandbox/rson_decompiler/BlockParEditor_1.9/BlockParEditor.exe",
    "game":     "C:/claude_sandbox/rson_decompiler/Space Rangers HD A War Apart",
    "decompiler": "C:/claude_sandbox/rson-decompiler"   // откуда импортировать srgi/srpkg/run
  }
}
```

Автодетект, если файла нет: сиблинги `../rson-decompiler`, `../rson_decompiler`
(как в `tools/build_lexicon.py`), внутри них — `rsmc/rsmc.exe`,
`RScript_4.14f/RScript.exe`, `BlockParEditor_1.9/BlockParEditor.exe`.

**Бандлить эти три бинарника нельзя** — ни у `RScript`/`rsmc`, ни у
`BlockParEditor`, ни у `RangersViewer`/`Cassandra` нет лицензии, а `srmod`
живёт под GPL v3. В репозитории — только пути в конфиге и понятная ошибка
«не найдено, укажи путь» + ссылка на релизы автора. Windows-only, как и раньше.

**2. Проектный — `srmod.json`** рядом с модом:

```jsonc
{
  "name": "MyMod",                       // == scriptName в main.rsm == имя .scr
  "install": "Mods/Artem/MyMod",         // путь от корня игры; от него зависят
                                         // CacheData.dat и INSTALL.TXT
  "languages": ["Rus", "Eng"],
  "primary_lang": "Rus",
  "script": {
    "engine": "rsmc",                    // rsmc | rson  (см. (г))
    "entry": "DATA/Script/MyMod.src/main.rsm"
  },
  "lang": { "merge_into": "txt" },       // txt (по умолчанию) | dat
  "media": { "gi_format": "argb", "gai_format": "delta" },
  "packages": ["DATA/Panels.pkg.src"],
  "deploy": { "mode": "junction" }       // junction | copy | off
}
```

**3. Поверх — флаги CLI и переменные `SRMOD_*`** (`SRMOD_RSMC`,
`SRMOD_RSCRIPT`, `SRMOD_BLOCKPAR`, `SRMOD_GAME`).

`srmod doctor` печатает, что откуда взялось: путь, уровень конфига, версию/пробу
(`rsmc build` без аргументов, проба RScript на `--split`/`--langdat` = 4.14f+,
наличие BPE и какой именно — 1.9 пишет `dat→txt` в cp1251, 2.0 в UTF-16LE+BOM),
и валидацию кодировок исходников мода.

Команды этапа 0: `srmod new` (скаффолд по раскладке выше), `build`, `watch`,
`doctor`, `lint`, `import`, `verify --gate`.

## (г) Запасная rson-ветка и гейт доверия

`rsmc` закрытый (исходники автор обещает после переписи на C++), поэтому
rson-ветка сборки остаётся в коде, а не в истории:

- `srmod build --engine rson` собирает из `DATA/Script/<Name>.rson` штатным
  RScript (`--cli -b <rson> <scr> <txt> --full` для 4.14f+, старая форма
  `-b -f` для ≤4.13f — выбор формы уже реализован в `run.py::_rscript_build_args`),
  через `_dlgwatch` (модалки), и слияние секции `Script` в язык делаем сами —
  прежний конвейер целиком.
- `srmod import <mod.rson>` — `RScript --cli -x … --split` в `<Name>.src/`.
  При импорте печатать предупреждение о классе потерь из пункта (б).6: мод,
  чьи тексты хранятся в `Lang` и подставляются `DText(CT("Script.X.N"))`,
  после `rsmc` потеряет эти вызовы. Пока `rsmc` это не чинит — импортированные
  моды с таким шаблоном собирать rson-веткой.
- `srmod verify --gate` — сборка обеими ветками и сравнение: сначала байты,
  при расхождении — декомпиляция обеих сборок нашим `decompiler.py` и сравнение
  структур с тремя уровнями нормализации (токены `Code`; схлопывание отступов;
  синтетические `Pos.*`, которых в `.scr` нет). Реализация и корпусный прогон —
  `rson_decompiler/_rsm_regress.py`, отчёт `_rsm_regress_out/REPORT.md`.

Гейт зелёный ⇒ можно жить на `rsmc`; красный на конкретном моде ⇒ этот мод
собирается rson-веткой, а расхождение уходит в issue автору `rsmc`.

### Результат корпусного прогона (2026-07-31)

Корпус: `decompile_result/` (330 rson) + `rsons/` — **539 файлов**, из них
компилируются штатным RScript 530. Прогон:
`python _rsm_regress.py` (≈10 мин, ~1 с на мод), отчёт —
`rson_decompiler/_rsm_regress_out/REPORT.md`.

**Гейт: 523/530 (98,7 %) сборок `rsmc` эквивалентны сборке RScript.**
(Прогонщик даёт 521: два его «расхождения» — `Cat_AsteroidStations` и
`PC_fem_rangers_` — сняты перепроверкой инструментами автора, см. (б).6.)

| Итог | Файлов |
|---|---|
| байт-в-байт | 172 |
| rson-декомпиляция обеих сборок идентична | 158 |
| совпало после нормализации кода (`-x` схлопывает `if(){}` в строку) | 11 |
| совпало после схлопывания отступов (rsmc пишет тело с отступом) | 71 |
| совпало после обезличивания имён (`-x` переименовывает дубли деклараций) | 8 |
| совпало после разрешения CT-ключей через таблицы обеих сборок | 89 |
| сверено декомпилятором RScript `-d` (наш не берёт эти сборки) | 12 |
| **расхождение** | **3** |
| **`rsmc` не собрал** | **6** |
| RScript сам не собирает (вне гейта) | 9 |

Из 3 расхождений после перепроверки инструментами автора остаётся **одно
настоящее**: `Mod_RevDiplomat` — `ChangeState(1)` компилируется в индекс
состояния, которое НАЗЫВАЕТСЯ `1` (пункт (б).7). Два других
(`Cat_AsteroidStations`, `PC_fem_rangers_`) — разница в разбиении кода на
строки, которую наш декомпилятор показывает как перенос `DText` (пункт (б).6);
`RScript --cli -d` на обеих сборках даёт одинаковый текст.

Все 6 несобравшихся — семейство `PC_final` из установленных модов: в коде
ответа диалога **на одну `{` больше, чем `}`** (`if(flagvar==0) {` закрыт не
до конца). RScript такой код принимает, парсер `rsmc` — нет
(`dialogs.rsm(line=…, symbol=3): expected "}"`). Воспроизводится целиком на
инструментах автора: `RScript --cli -d` шиппящегося
`Mods/Reflection/RefAltStartOnlyPirates/DATA/Script/PC_final.scr` → `--cli -x
--split` → `rsmc build` = ошибка, при том что `--cli -b` того же `.rson`
собирается без единого замечания.

Нормализации, которыми пришлось обвесить сравнение (иначе шум топит сигнал),
сами по себе — список того, чем `.rsm`-сборка законно отличается от rson-сборки:
номера CT-ключей у компиляторов свои (сравнивать надо тексты, но **только по
своей секции** — `CT('Script.PC_final.186')` в чужую таблицу лезть нельзя),
имена одноимённых деклараций `-x` разводит, координаты узлов в `.scr` не
хранятся вовсе.
